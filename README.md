# 双人房 · 情侣互动页

成年情侣向的双人小游戏：**转盘** 与 **真心话 / 大冒险**。
支持单人自娱，也支持两台手机远程同房——一个人转，两个人的屏幕同时转。

纯静态站点，零后端、零依赖。双人同步靠 **WebRTC 点对点直连**，两个人之间不经过任何服务器。

---

## 在线地址

```
https://love.hser.ren
```

托管在 GitHub Pages（仓库 `csdsq/love-room`），绑定自定义域名 `love.hser.ren`，证书由 GitHub 自动签发续期。

手机打开就能用，两个人的手机各开一个，输同一个匹配码即同房。

## 两个人怎么玩

1. A 在首页点 **「开一间双人房」** → 生成 6 位匹配码（自动复制）
2. A 把数字发给 B（微信、短信都行）
3. B 在首页点 **「我有匹配码」** → 输入这 6 位数字
4. 连上之后，任意一方点 **「开始今晚」** → 两边同时进入玩法页

之后所有操作都是双向的：转盘、抽卡、倒计时、积分、回合、安全词。

**访问密码**：进入页面前需输访问密码（固定为 `love`，代码内 `LOCK_PASS` 可改）。输对一次后该设备记 30 天（存 localStorage，类似 cookie，密码本身不变），期间免输直达；过期后重新询问一次。

## 玩法

### 转盘
四种主题，越往后越深：

| 主题 | 调性 |
|------|------|
| 入门 | 定称呼、跪姿、请安、报备 —— 先把「服从」说出口 |
| 服从 | 双手背后、跪着报数、指定展示、主动请罚 |
| 羞耻 | 自述、接受评点、自己束腕、羞耻台词十遍、报数认罚 |
| 契约 | 立规矩、定罚则、感官剥夺、安静束缚、全身评估、边界协商 |

全部内容均为**远程可执行**（说得出口、镜头前做得到），不包含拥抱、牵手等需要同处一室的动作。

### 真心话 / 大冒险
四档递进：**L1 入门 → L2 服从 → L3 羞耻 → L4 契约**。
每档 16 张真心话 + 16 张大冒险，共 128 张，另有自定义卡池可以写自己的。

### 附加机制
- **回合制**：完成一项自动换人，回合归属是房间级共享的，两边不会各说各话
- **亲密度积分**：完成一项 +1，两边同步

### 聊天
进入**转盘**或**真心话 / 大冒险**后，页面底部常驻聊天区（默认约 1/3 屏记录 + 输入框，记录多了向上滑动），支持**文字、语音（最长 2 分钟）、图片、视频**：

- **三态可调**：点 ⤢ 展开接近全屏，点 ▾（或点标题栏）收成一条只显示未读数，再点恢复
- 全部走 WebRTC DataChannel **点对点直传**，不经过任何服务器，也不写 localStorage / IndexedDB——关掉页面，聊天就没了
- 大文件自动分片（12KB/片）+ 背压控制，接收端实时显示进度条
- 发图片 / 视频会先问「拍照（录像）/ 从相册选择」，拍照用前置摄像头
- 图片自动压缩到 1280px / JPEG 72%，控制体积
- 限制：图片 ≤ 16MB，视频 ≤ 40MB；语音用 MediaRecorder 现场录
- 语音播放时有**动态波形 + 暂停键**，再点一下即停
- 对方掉线时输入框禁用、传输中的文件标记失败
- **今晚记录**：抽到过什么，按时间倒序留痕
- **一键计时**：结果卡上点「开始计时」，两个人同时开始倒数
- **安全词**：游戏页不放常驻按钮 —— 回到「选个玩法」页点红色「现在停下」，或直接喊一声「红灯」

## 本地运行

不需要 `npm install`，只需要 Node：

```bash
node server.js            # → http://localhost:3000
PORT=8080 node server.js  # 换端口
```

`server.js` 只做一件事：把 `public/` 端出来。它不参与任何游戏逻辑。

## 部署

仓库已配置 GitHub Actions，推送到 `main` 就自动发布 `public/` 到 Pages：

```
.github/workflows/pages.yml
```

改完页面推上去，等 Actions 跑完（约 30 秒）刷新即可。

- 仓库：`https://github.com/csdsq/love-room`
- 站点：`https://love.hser.ren`（Pages 自定义域名，已强制 HTTPS）
- DNS：Cloudflare 上 `love` → CNAME → `csdsq.github.io`（DNS only，证书走 GitHub）

> **唯一生效路径是 GitHub Pages。** 仓库里的 `deploy/` 是早期 ECS（nginx + systemd）方案，
> 已停用，不要再执行；保留仅作历史参考，完整说明见根目录 `DEPLOY.md`。

### 如果 `git push` 推不上去

有些网络里 git 的 HTTPS POST 会被代理掐断（`CONNECT tunnel failed, response 502`），
但 GitHub API 是通的，这时用仓库自带的发布脚本：

```bash
GITHUB_TOKEN=你的token node tools/deploy.mjs "这次改了什么"
```

它会比对本地文件和远端 Git tree 的 sha，只提交真正变化的部分，然后自动触发 Pages 重新部署。
token 从这个环境变量读，不写进任何文件。

想部署到别的地方（Cloudflare Pages / Netlify / Vercel / 任意静态托管）：
把 `public/` 目录整个上传，站点根指向它，就完事了。不需要任何构建命令。

## 技术说明

### 网络连通性（为什么"同一个 WiFi 能连、都用流量就连不上"）

PeerJS 默认只带 Google 的 STUN（`stun.l.google.com`），在国内运营商网络下经常拿不到响应 → 收集不到公网映射地址 → 打洞失败。本项目已在 `public/js/net.js` 的 `ICE_SERVERS` 里换成一组国内可达的 STUN（小米 / B 站 / 芒果 TV / Cloudflare），并把 PeerJS 内置的 `*.turn.peerjs.com`（已无法解析）覆盖掉；同时在 `TURN_SERVERS` 里接了自建 coturn（`8.149.139.66:3478`，仅打洞失败时使用）。

- **同一个 WiFi**：靠 host 候选直连，不依赖 STUN，永远可用。
- **两端不同网络（流量↔流量、流量↔WiFi）**：靠 STUN 打洞。多数家庭宽带 + 部分运营商可通。
- **两端都在运营商 CGNAT 后面（对称 NAT）**：打洞在原理上不可能，必须有 TURN 中继。`TURN_SERVERS` 已配置自建 coturn（`turn:8.149.139.66:3478`，UDP/TCP），打洞失败时自动降级为中继，诊断面板会显示「中继转发」。

排查入口：房间页「连不上？看连接诊断」，显示 ICE 状态、各类候选数量、实际通路和当前生效的 STUN/TURN 列表。

```
public/
├── index.html                所有页面（单页切换）
├── css/style.css             深色玫瑰主题，移动端优先
├── js/
│   ├── vendor/peerjs.min.js  点对点连接库（本地内置，不依赖 CDN）
│   ├── net.js                WebRTC 传输层：开房 / 加入 / 心跳 / 断线检测
│   ├── data.js               内容库：4 主题 × 10 扇区（共 40）、128 张卡（4 档 × 32）、11 条安全规则
│   └── app.js                状态机 + 同步协议 + Canvas 转盘
└── robots.txt
```

### 同步是怎么做的

没有服务器，两个人要同步，只能直连：

1. 房主用 `duo-r-<6位码>` 作为自己的 Peer ID 向公共信令服务器登记
2. 对方填入这 6 位数字，也用同一套规则敲这个 ID
3. 信令服务器只负责交换一次连接信息，之后数据走浏览器之间的**加密 DataChannel**
4. 转盘不传角度，只传「第几格 + 转几圈」，两边用同一个公式算，所以角度一定一致
5. 双方每 4 秒互发心跳；**45 秒没动静只把界面降级成「Ta 暂时不在」，不拆连接**
6. 通道真的断了（`conn.close` / `ICE failed`）走静默重拨，退避 0.8s→8s，最多 12 轮
7. 只有通道连续 3 分钟都起不来，才判定「Ta 离开了」并提示，而不是一掉线就报错

### 切到后台会怎样

浏览器不允许网页在后台长时间保活，所以目标不是「永不掉线」，而是「用户永远不需要手动重连」：

| 场景 | 表现 |
|---|---|
| 切到微信几分钟再回来（Android） | 连接可能压根没断，回来直接继续（实测冻结 55 秒仍 `connOpen=true`） |
| iPhone 切走 | Safari 会挂起页面，通道必断；回来 1–3 秒静默接上，不用点任何按钮 |
| 页面被系统回收后重开 | 用 `sessionStorage` 里的房间记号自动回到原房间，不用重新输码 |
| 对方关掉页面 | 45 秒后显示「Ta 暂时不在」，3 分钟内没恢复才提示离开；聊天记录不清空 |
| 期间对方发的消息 | 通道还在就排队送达；通道已断则收不到（纯网页没有服务端离线消息） |

主动点「返回」退出房间才会清掉房间记号（`P2P.leave()`），刷新不会。

### 已知限制

- **必须两个人同时在线**：这是点对点，没有服务器帮忙存消息，一方关掉页面另一边就没法推进
- **依赖公共信令服务器**（`0.peerjs.com`）：它挂了就开不了新房，已经连上的不受影响。要更稳可以自建 [PeerServer](https://github.com/peers/peerjs-server) 然后改 `net.js` 里的 `Peer` 配置
- **极端网络走中继**：双方都在严格的对称 NAT / CGNAT 后面时，STUN 打洞不可能成功，会自动走自建 TURN。中继带宽受 ECS 出口带宽限制，传大视频会比直连慢
- **房间码是 6 位数字**：方便口头/文字传递，但理论上存在撞号（撞了会自动换一个）

## 内容与分寸

页面里的内容写到「动作与氛围」为止，不写器官级的细节。分级是刻意做的：

- 四档由浅入深，**默认停在最浅那档**，往深了走要自己点
- 「安全规则」页写着安全词、黄灯、饮酒不玩束缚、不绑颈部、事后收尾
- 安全词不是装饰——按下去两边一起停，谁也不能单方面继续

真到那一步，两个人自己说得出口的东西，比页面上写得出来的更合适。
